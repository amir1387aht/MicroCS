category: Optional GUI and TFT
requires: Compiler

[lvgl_label.cs] LVGL label (headless or installed backend)
requires: Compiler, LVGL
Create an actual LVGL label and pump a bounded render loop. Needs optional LVGL8.4/9.4 firmware. A headless sink does not imply a physical display.

[lvgl_button.cs] LVGL pointer and button events
requires: Compiler, LVGL
Use script-fed pointer input for a real LVGL hit test and bounded event polling. The native input driver may replace script input in hardware firmware.

[tft_draw.cs] TFT_eSPI drawing and text
requires: Compiler, TFT
Draw RGB565 primitives and compiled font text. Needs a reviewed firmware TFT setup and actual hardware; no universal pinout is assumed.

[tft_lvgl.cs] TFT_eSPI + LVGL bridge
requires: Compiler, TFT, LVGL
Attach the synchronous TFT backend before constructing a GUI. Dispose the GUI before detaching and disposing its display; no DMA or hardware presence guarantee.

[tft_sprite.cs] TFT_eSPI RAM sprite and synchronous push
requires: Compiler, TFT, TFT.Sprite
Draw into a bounded actual16-bit native sprite, read its RAM pixel and push to reviewed hardware. Dispose child before parent; no DMA or physical-readback claim.

[tft_packed.cs] Native TFT palette and bitmap RAM
requires: Compiler, TFT, TFT.Sprite, TFT.Palette, TFT.Bitmap
Use strict4-bit palette indices and1-bit pixels with real native RAM readback. Safe palette allocation, padded rows and parent-wide bitmap mapping; no physical IO.
